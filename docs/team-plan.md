# Team Plan

## Roles (combine if team is small)
| Role | Owner | Responsibility |
|---|---|---|
| Product / challenge lead | | Clarify problem, acceptance criteria, judging priorities |
| Technical lead / architect | | Boundaries, interfaces, unblock decisions |
| Backend / data | | API, business logic, persistence |
| Frontend / UX | | Main user journey and visible feedback |
| AI / retrieval | | Model integration, prompts, retrieval, usage tracking |
| QA / demo / TPM | | Test plan, integration, timebox, presentation |

## Working agreement
- One shared task board; every task has an owner and a testable outcome.
- Agree on API/data contracts before parallel work.
- Merge small changes frequently; integrate early.
- Keep the main branch runnable.
- Raise blockers early; timebox investigations.
- Do not share code, keys, or ideas across teams if event rules prohibit it.
- Only the designated person resolves cross-team technical conflicts.

## Suggested 24-hour checkpoints (adjust to event schedule)
- First 30–45 min: understand challenge, define users and judging criteria.
- Next 45–60 min: choose MVP workflow, architecture, contracts, task owners.
- Early build: get one end-to-end vertical slice running.
- Midpoint: feature freeze for risky extras; focus on integration and tests.
- Final stretch: clean run, bug fixes, demo rehearsal, presentation and submission.
- Follow event announcements and scoring instructions over this generic plan.
